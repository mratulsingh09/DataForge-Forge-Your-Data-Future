Functions 
- A function is a reusable block of JavaScript code designed to perform 
a particular task.  
- Instead of writing the same statements repeatedly, we can place 
them inside a function and call the function whenever required.  
- A function executes when it is called or invoked. 
Why Functions Are Used 
 To avoid repeating the same code. 
 To divide a large program into smaller tasks.  
 To improve code readability. 
 To make code easier to test and maintain. 
 To reuse the same logic with different values. 
Function Syntax 
function functionName(parameters) { 
    // statements 
} 
function is the keyword used to declare a function. functionName is the 
name given to the function. parameters are optional inputs received by the 
function. 
Function Declaration 
A function declaration defines a function using the function keyword.  
function greet() { 
    console.log("Hello Students"); 
} 
The above code only defines the function. The statements inside it execute 
when the function is called. 
--- Page 2 ---
Calling a Function 
Calling a function means executing the function. 
function greet() { 
    console.log("Hello Students"); 
} 
 
greet(); 
Output: Hello Students 
 
Type of Functions 
1. Function Without Parameters 
A function can perform a task without receiving any input values.  
function welcome() { 
    console.log("Welcome to JavaScript"); 
} 
 
welcome(); 
2. Function With Parameters 
Parameters are variables written in the function definition. They receive 
values when the function is called. 
function greet(name) { 
    console.log("Hello " + name); 
} 
 
greet("ABC"); 
Here, name is the parameter and "ABC" is the argument passed to the 
function.

Return Statement 
The return statement sends a value from the function back to the place 
where the function was called. 
function add(a, b) { 
    return a + b; 
} 
 
let result = add(10, 20); 
console.log(result); 
Output: 30 
 return ends the execution of the function. 
 The returned value can be stored in a variable or used in another 
expression. 
 A function does not need to use return if it only performs an action.

Function With Return Value

    return number * number;

let result = square(5); 
console.log(result);

Function Without Return Value 
A function can perform an action without returning a value. 
function displayMessage() { 
    console.log("Welcome"); 
} 
 
displayMessage(); 
Passing Different Values 
The same function can be reused with different arguments.  
function greet(name) { 
    console.log("Hello " + name); 
} 
 
greet("ABC"); 
greet("DEF"); 
greet("GHI"); 
The function is written once but can be called multiple times with different 
values.

Local Variables in a Function 
A variable declared inside a function is normally available only within that 
function. 
function showAge() { 
    let age = 20; 
    console.log(age); 
} 
 
showAge(); 
 The variable age is local to showAge(). 
 It should not be directly accessed outside the function.  
Default Parameters 
A default parameter provides a value when an argument is not supplied. 
This feature is commonly used with modern JavaScript and is also covered 
under ES6 Features. 
function greet(name = "Guest") { 
    console.log("Hello " + name); 
} 
 
greet(); 
greet("ABC"); 
Output: 
Hello Guest 
Hello ABC 
Function Expression / Lambda Function 
A function can also be stored in a variable. This is called a function 
expression.

    return a + b; 
}; 
 
console.log(add(10, 20)); 
Output: 30 
 The function is assigned to the variable add. 
 The function can be called using add().

Form Validation 
- Form validation is the process of checking the data entered by a user 
before the form is submitted.  
- Validation helps identify incorrect or incomplete input.  
- It can provide a message to the user when the entered data is invalid.  
- Validation can be performed before sending form data to the server.  
Basic Form Validations  
 Name 
 Password 
 Mobile 
 Email 
 Date 
1. Name Validation 
- Name validation checks whether the user has entered a name and 
whether the name contains acceptable characters. 
- Name should not be empty and can be checked using a regular expression 
that allows alphabetic characters and spaces. 
let name = document.getElementById("name").value;  
 
let namePattern = /^[A-Za-z ]+$/; 
 
if (name === "") { 
    console.log("Name is required"); 
} else if (!namePattern.test(name)) { 
    console.log("Enter a valid name"); 
} else { 
    console.log("Valid name"); 
} 
--- Page 2 ---
Name Validation Rules 
 Name should not be empty. 
 Name should contain alphabetic characters and spaces.  
 Special characters and numbers can be rejected when the application 
requires a simple alphabetic name. 
2. Password Validation 
- Password validation checks whether the user has entered a password and 
whether it satisfies the required password rules. 
- A common basic rule is to require a minimum number of characters. 
Applications can define stronger rules depending on their security 
requirements. 
let password = document.getElementById("password").value;  
 
if (password === "") { 
    console.log("Password is required"); 
} else if (password.length < 8) { 
    console.log("Password must contain at least 8 characters");  
} else { 
    console.log("Valid password"); 
} 
Password Validation Rules 
 Password should not be empty. 
 A minimum length should be defined by the application.  
 For stronger validation, applications may require uppercase letters, 
lowercase letters, numbers, and special characters. 
 Passwords should not be displayed openly on the page.  
 
 
--- Page 3 ---
3. Mobile Validation 
- Mobile validation checks whether the entered mobile number follows the 
format expected by the application. 
- For a simple example, a 10 -digit numeric mobile number can be checked 
using a regular expression. 
let mobile = document.getElementById("mobile").value;  
 
let mobilePattern = /^[0-9]{10}$/; 
 
if (mobile === "") { 
    console.log("Mobile number is required"); 
} else if (!mobilePattern.test(mobile)) { 
    console.log("Enter a valid 10-digit mobile number"); 
} else { 
    console.log("Valid mobile number"); 
} 
Mobile Validation Rules 
 Mobile number should not be empty. 
 For this basic example, exactly 10 digits are required. 
 Only numeric digits are accepted. 
 The exact mobile-number format should match the application's 
requirements and country rules. 
4. Email Validation 
- Email validation checks whether the entered value follows a basic email 
address pattern. 
let email = document.getElementById("email").value;  
 
let emailPattern = /^[^\s@]+@[^\s@]+\.[^\s@]+$/;

if (email === "") {

Email Validation Rules 
 Email should not be empty. 
 A basic email pattern should be checked. 
 The value should contain an appropriate local part, @ symbol, and

 Client-side pattern checking is only a basic format check; it does not 
prove that an email address exists.

Introduction to Version Control System (VCS) 
- A Version Control System (VCS) is a software tool used to track changes made to 
files and source code over time.  
- It helps developers maintain different versions of a project and understand what 
changes were made. 
- VCS is especially useful when multiple developers work on the same project

Why Version Control is Needed 
Without version control, developers may create many copies of the same project, such 
as: 
 project_final 
 project_final_new 
 project_final_latest 
This approach makes it difficult to identify which version is correct and who made a 
particular change. 
A VCS provides a systematic way to: 
 Track changes in source code. 
 Maintain the history of a project.

 Identify who made a change. 
 Restore an earlier version when required. 
 Allow multiple developers to work on the same project.  
 Create separate development paths using branches.

What is GIT 
- GIT is a distributed version control system used to track changes in source code 
and manage different versions of a project. 
- GIT was originally created by Linus Torvalds in 2005  
- GIT is commonly used with platforms such as GitHub, GitLab, and Bitbucket for 
remote repository hosting and collaboration. (GitHub is preferable) 
Why is GIT Used 
 To maintain the history of source-code changes. 
 To work on different features separately using branches.  
 To compare changes between versions. 
 To restore previous versions of files. 
 To support collaboration between developers. 
 To work locally and synchronize changes with remote repositories.  
Features of GIT 
 Distributed – Each developer can have a complete local repository.  
 Version History – Changes can be recorded and reviewed.  
 Branching – Developers can create separate branches for features or fixes.  
 Merging – Changes from different branches can be combined.  
 Collaboration – Multiple developers can work on the same project.  
 Data Integrity – GIT uses checksums to identify and protect stored c ontent.

Working with Branches 
- GIT branch is a separate line of development in a repository. Branches allow 
developers to work on features, fixes, or experiments without directly changing the 
main development line. 
- A branch can be created from an existing point in the project's history. Developers 
can work on the branch, create commits, and later merge the changes into another 
branch. 
Why Branches are Used 
 To develop new features separately.  
 To fix bugs without disturbing the main development line.  
 To allow multiple developers to work on different tasks.  
 To test or experiment with changes safely.  
 To organize project development.  
 To combine completed work using merging.  
Understanding the Main Branch 
The main branch is commonly used as the primary branch of a repository. Depending 
on the repository or project, it may be named main or another name.  
The important idea is that developers can create separate branches from the main 
development line and work independently.  
main 
  | 
  +------ feature-login 
  | 
  +------ feature-payment 
 
Checking the Current Branch 
Command 
git branch 
Purpose of the Command 
- The git branch command displays local branches. The current branch is normally 
indicated with an asterisk (*). 
Example 
--- Page 2 ---
git branch 
 
* main 
  feature-login 
  feature-payment 
In this example, the asterisk indicates that main is the current branch.  
 
Creating a New Branch 
Command 
git branch feature-login 
Purpose of the Command 
- Creates a new branch named feature-login without automatically switching to it. 
Example 
git branch feature-login 
git branch 
 
After creation, the new branch appears in the branch list, but the current branch 
remains unchanged. 
Switching to a Branch 
Command 
git switch feature-login 
Purpose of the Command 
- Switches the working directory to the specified existing branch.  
Example 
git switch feature-login 
git branch 
 
The asterisk now appears next to feature-login. 
 
Creating and Switching to a Branch 
--- Page 3 ---
Command 
git switch -c feature-login 
Purpose of the Command 
- Creates a new branch and switches to it in one command.  
Example 
git switch -c feature-login 
git branch 
 
This is a convenient command when starting work on a new feature.  
Note: Alternative Command 
  git checkout -b feature-login 
This older command can also create and switch to a branch. For new classroom 
examples, git switch is clearer because it is specifically designed for branch switching.  
 
Viewing Branches 
Local Branches 
git branch 
        Purpose: Displays local branches.  
Branches with More Information 
git branch -v 
        Purpose: Displays local branches with information about their latest    commits.  
 
Working with a Branch 
Once a developer switches to a branch, changes can be made and committed normally.  
git switch feature-login 
 
# Modify project files 
 
git status 
git add . 
git commit -m "Added login feature"  
--- Page 4 ---
The commit is created on the current branch. The main branch is not automatically 
updated by this commit. 
Note: Branch and Commit Relationship 
Each branch points to a line of commits. When a new commit is created on a branch, 
that branch moves forward to include the new commit.  
main 
A --- B 
 
feature-login 
A --- B --- C --- D 
Here, commits C and D belong to the feature-login development line. The main branch 
still points to B until the feature branch is merged. 
 
Merging Branches 
Merging is the process of combining changes from one branch into another branch.  
Basic Workflow 
git switch main 
git merge feature-login 
Purpose of git merge 
The git merge command combines the changes from the specified branch into the 
currently switched branch. 
Example 
git switch main 
git merge feature-login 
 
Here, feature-login is merged into main. The developer must first switch to the branch 
that should receive the changes. 
Note: 
 The branch being merged into is the current branch.  
 The branch named in git merge is the source of the changes.  
 After a successful merge, the changes from the source branch become part of the 
target branch.

Command

Purpose of the Command 
        Renames a local branch. 
Example

Deleting a Branch 
Command 
git branch -d feature-login 
Purpose of the Command 
- Deletes the specified local branch when its changes have been merged or Git 
considers it safe to delete. 
Example 
git switch main 
git branch -d feature-login 
 
A branch should normally be deleted after its work has been merged and is no longer 
required. 
Note: Force Deleting a Branch 
git branch -D feature-login 
 
Purpose: Force deletes the local branch. This should be used carefully because it can 
remove a branch that contains unmerged work.

Remote Repository 
- A remote repository is a GIT repository stored on another system or on an online 
repository hosting platform. It allows developers to store, share, and 
synchronize project history with other developers.  
 
- A local repository is stored on the developer's computer, while a remote 
repository is stored separately and can be accessed through a network.

Local Repository Remote Repository

connecting to a network.

Why Remote Repositories are Used 
 To store a shared copy of a project.  
 To back up project history outside the local computer.  
 To share code with other developers. 
 To synchronize work between developers. 
 To support collaboration using branches and commits.  
 To make a project accessible from multiple development environments.
